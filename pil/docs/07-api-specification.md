# API Specification (v1 outline)

Full machine-readable spec will be generated by FastAPI (`/api/v1/openapi.json`) once implemented; this document is the authoritative pre-implementation contract. All endpoints under `/api/v1`, versioned; breaking changes require `/api/v2`. OpenAPI docs UI (`/docs`) disabled or admin-gated in production.

## Conventions
- Auth: `Authorization: Bearer <access_token>` for API calls; refresh via httpOnly cookie only, never in JS-readable form.
- CSRF token required (header `X-CSRF-Token`) on all mutating requests originating from browser session cookies.
- All list endpoints paginated (`?cursor=&limit=`), max `limit` enforced server-side (e.g. 100).
- Errors: RFC 7807 `application/problem+json` — `{type, title, status, detail, instance}`, no stack traces or internal identifiers ever leaked in production error bodies.
- Standard status codes: 200/201/204 success; 400 validation; 401 unauthenticated; 403 authorization denied (never leaks whether resource exists); 404 only when 403 would itself leak sensitive existence info is not a concern; 409 conflict; 422 semantic validation; 429 rate limited; 5xx generic (no detail).

## Auth
```
POST   /auth/login                  {alias, password} -> mfa_challenge | tokens
POST   /auth/mfa/verify             {challenge_token, totp_code} -> tokens
POST   /auth/refresh                (cookie) -> new access token + rotated refresh cookie
POST   /auth/logout                 -> revoke current session
POST   /auth/logout-all             -> revoke all sessions for current user
POST   /auth/password/change        {current_password, new_password}
POST   /auth/mfa/enroll             -> secret + provisioning uri (once)
POST   /auth/mfa/enroll/confirm     {totp_code}
POST   /auth/mfa/backup-codes/regenerate
```

## OpenAPI Governance
- Every request/response modeled with explicit Pydantic schemas (`extra="forbid"`); no bare `dict` payloads.
- Security schemes declared (`bearerAuth`), applied per-route via FastAPI `dependencies=[...]`, not globally assumed.
- CI step validates the generated OpenAPI spec against the checked-in contract to catch accidental breaking/undocumented changes.
